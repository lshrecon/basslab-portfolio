# BassLab：ベース練習アプリ

2026年10月9日版。v26を基にUTF-8処理と未測定時刻の扱いを修正した、採用検討用のソース抜粋です。実行可能なアプリ配布版ではありません。

## 目的・構成

自分の演奏を録音し、分析結果を見ながら気になる箇所を聴き直すWindows向けアプリを、生成AIも活用して個人開発しています。

- React：練習設定・結果表示・聴き直し操作。
- Node.js：ローカルAPI、保存、分析処理との連携、音声の提供。
- C++／WASAPI：Windowsの音声入力と録音処理。

## 改善例：再生位置と測定値を分ける

音の開始時刻を推定できない場合にも、聴き直し用の候補位置を測定値として集計していました。仮の2音で、未測定の音Aを＋60ms、音Bを−20msとして平均すると＋20msになります。

修正後は音Aを未測定として集計から除き、音Bだけの−20msを表示します。聴き直す位置は別に保持し、結果を保留した理由も示します。これは合成例で、精度改善率ではありません。

別の修正では、UTF-8文字がプロセス通信のバイト境界で分割された際の文字化けに対し、StringDecoderで文字を復元するようにしました。

## 検証済みの範囲

| 対象 | 確認したこと | 限界 |
|---|---|---|
| 修正前の原本v25 | Focusrite入力2で遅延測定、60 BPM・A弦32音の録音・保存・分析・再生、ベースとクリックの聴取 | 単一装置・単一条件の確認 |
| v26を基にした別検証版 | 21件の回帰検査、JSXビルド、実際のHTTPによる保存・結果・音声応答 | HTTP入力は合成メタデータと無音 |

21件の内訳はUTF-8が11件、タイミングが10件です。最近のAI支援による検証であり、原本v25の実機確認とは別です。装置プロセスには代替オブジェクトを使う検査もあり、録音・分析精度を保証しません。

修正版の全画面操作・実機確認・リリース検査は未完了です。通常の録音起動は保留しています。二つの推定が32候補中28件で一致したことは精度87.5%を意味せず、独立した正解時刻との比較が必要です。過去の70 BPMに対する約34.7 BPMや開始指標の差も、指の癖が原因だと証明するものではありません。

## 読む順序と小さな検査

- `app/src/65-PracticeFlow.jsx` → `bridge/practice-server.cjs`：画面から録音処理への連携。
- `bridge/practice-controller.cjs`：C++プロセスとの通信、UTF-8処理。
- `native/practice-engine.cpp`：録音処理の入口。
- `analysis/signal-pipeline.cjs`、`analysis/onset-states.cjs`：推定と状態分類。
- `click/model.cjs`：測定値と再生位置の区別。
- `app/src/60-ObservationResults.jsx`：結果・保留理由の表示。

Node.jsがある環境で、ZIPのルートから次を実行します。実装コードには追加ファイル・設定が必要ですが、この2つの回帰検査は同梱しています。

```text
node --test tests/protocol-utf8.test.cjs tests/click-timing.test.cjs
```

## 含めていないもの

実録音・利用者セッション・装置ID・校正記録・モデル入力音声・実行ファイル・ランタイム・起動用設定・完成版ランチャーを含めていません。Reactのコンパイル済み配布物も含めません。この抜粋からアプリ全体をそのまま起動する構成ではありません。

`ANALYSIS-FREEZE.json` と `BENCHMARK-DECISION.json` は分析条件と未達成の判定を読むために含めています。そこで参照される評価用音声・元データは別資料であり同梱していません。ベンチマークの3条件は未達成です。

第三者のコードに付属するライセンス表記を保持しています。`MANIFEST.json` に配布ファイルの対応とハッシュを記録しています。今回AIが行った修正・検査と、本人が行った原本の録音・聴取確認を区別します。
