# BassLab: 베이스 연습 앱

기존 검사 결과를 포함한 일본어 원본 ZIP의 README를 본인 열람용으로 옮긴 문서로, 아래 ‘ZIP’·‘배포 자료’는 일본어 원본 코드 묶음을 뜻합니다.

2026년 10월 9일판. v26을 바탕으로 UTF-8 처리와 미측정 시각의 취급을 수정한 채용 검토용 소스 발췌본입니다. 실행 가능한 앱 배포판은 아닙니다.

## 목적·구성

자신의 연주를 녹음하고 분석 결과를 보면서 신경 쓰이는 부분을 다시 듣는 Windows용 앱을, 생성 AI도 활용해 개인 개발하고 있습니다.

- React: 연습 설정·결과 표시·다시 듣기 조작.
- Node.js: 로컬 API, 저장, 분석 처리와의 연결, 오디오 제공.
- C++／WASAPI: Windows 오디오 입력과 녹음 처리.

## 개선 예: 재생 위치와 측정값을 분리

음의 시작 시각을 추정할 수 없는 경우에도 다시 듣기용 후보 위치를 측정값으로 집계하고 있었습니다. 가상의 2개 음에서, 미측정인 음 A를 ＋60ms, 음 B를 −20ms로 취급해 평균을 내면 ＋20ms가 됩니다.

수정 후에는 음 A를 미측정으로 취급해 집계에서 제외하고, 음 B만의 −20ms를 표시합니다. 다시 듣기 위치는 별도로 유지하고 결과를 보류한 이유도 표시합니다. 이는 합성 예제이며, 정확도 개선율이 아닙니다.

다른 수정에서는 프로세스 통신 중 UTF-8 문자가 바이트 경계에서 나뉠 때 발생하는 글자 깨짐에 대응해, StringDecoder로 문자를 복원하도록 했습니다.

## 검증된 범위

| 대상 | 확인한 내용 | 한계 |
|---|---|---|
| 수정 전 원본 v25 | Focusrite 입력 2에서 지연 측정, 60 BPM·A현 32음의 녹음·저장·분석·재생, 베이스와 클릭 청취 | 단일 장치·단일 조건 확인 |
| v26을 바탕으로 한 별도 검증판 | 회귀검사 21개, JSX 빌드, 실제 HTTP를 통한 저장·결과·오디오 응답 | HTTP 입력은 합성 메타데이터와 무음 |

21개 중 UTF-8 검사는 11개, 타이밍 검사는 10개입니다. 최근 AI의 도움을 받은 검증으로, 원본 v25의 실제 장치 확인과는 별개입니다. 장치 프로세스에 대체 객체를 사용하는 검사도 있으며, 녹음·분석 정확도를 보장하지 않습니다.

수정판의 전체 화면 조작·실제 장치 확인·릴리스 검사는 완료되지 않았습니다. 일반 녹음 실행은 보류하고 있습니다. 두 추정이 후보 32개 중 28개에서 일치했다는 것이 정확도 87.5%를 뜻하지 않으며, 독립적인 정답 시각과 비교해야 합니다. 과거 70 BPM에 대해 약 34.7 BPM이 나온 결과나 시작 지표의 차이도 손가락 습관이 원인임을 증명하지는 않습니다.

## 읽는 순서와 작은 검사

- `app/src/65-PracticeFlow.jsx` → `bridge/practice-server.cjs`: 화면에서 녹음 처리로의 연결.
- `bridge/practice-controller.cjs`: C++ 프로세스와의 통신, UTF-8 처리.
- `native/practice-engine.cpp`: 녹음 처리의 시작 부분.
- `analysis/signal-pipeline.cjs`, `analysis/onset-states.cjs`: 추정과 상태 분류.
- `click/model.cjs`: 측정값과 재생 위치의 구분.
- `app/src/60-ObservationResults.jsx`: 결과·보류 이유 표시.

Node.js가 있는 환경에서 ZIP의 루트 폴더에서 다음 명령을 실행합니다. 구현 코드에는 추가 파일·설정이 필요하지만, 이 2개 회귀검사는 포함돼 있습니다.

```text
node --test tests/protocol-utf8.test.cjs tests/click-timing.test.cjs
```

## 포함하지 않은 항목

실제 녹음·사용자 세션·장치 ID·보정 기록·모델 입력 오디오·실행 파일·런타임·실행 설정·완성판 런처를 포함하지 않았습니다. React의 컴파일된 배포 파일도 포함하지 않습니다. 이 발췌본으로 앱 전체를 그대로 실행할 수 있는 구성은 아닙니다.

`ANALYSIS-FREEZE.json`과 `BENCHMARK-DECISION.json`은 분석 조건과 미달성 판정을 읽을 수 있도록 포함했습니다. 이 파일들에서 참조하는 평가용 오디오·원자료는 별도 자료이며 포함하지 않았습니다. 벤치마크의 3개 조건은 달성하지 못했습니다.

제3자 코드에 포함된 라이선스 표기를 유지했습니다. `MANIFEST.json`에 배포 파일의 대응 관계와 해시를 기록했습니다. 이번에 AI가 수행한 수정·검사와, 본인이 원본에서 수행한 녹음·청취 확인을 구분합니다.
